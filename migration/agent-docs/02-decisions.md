## 2026-09-11: Use MyST (`mystmd`) directly rather than the `jupyter-book` wrapper

`jupyter-book` 2.x is a white-labelled `mystmd` CLI (same commands, same `myst.yml`).
Using `mystmd` directly matches the reference site (`manywidgets-playground`) and
the anywidget static-export plugin ecosystem we intend to adopt later. Installed
from PyPI via `uv` so contributors do not need a separate Node install (`mystmd`
bootstraps Node >= 20 through `nodeenv` when none is found).

## 2026-09-11: `myst.yml` lives in `docs/source/`; no files move

Options: keep `docs/source/` as the MyST project root; flatten to `docs/`; flatten
to the repo root. Chosen: keep `docs/source/`. Zero file moves means every relative
image and notebook link stays valid and the 13 open branches do not hit rename
conflicts. Flattening can be done later with a single `git mv`.

## 2026-09-11: Hosting stays on ReadTheDocs (`build.commands`)

RTD serves the custom domain, the `/en/latest`, `/en/stable`, `/en/develop` versions
and the frozen `/en/last-ade-release` version that the homepage links to. mystmd has
an official RTD recipe (`myst init --readthedocs`) using `build.commands` with a
`nodejs` tool. GitHub Pages was rejected for phase 1 because it would lose the
versioning and custom domain. Moving the static build to S3 is a possible later
step if RTD becomes limiting (for example for custom widgets).

PDF and epub outputs, currently produced by RTD's Sphinx builders, are not
produced in phase 1. Recorded in `04-compromises.md`.

Safety: RTD reads `.readthedocs.yml` from the branch it builds, so the new config
only applies to this branch (and a PR preview of it, if previews are enabled on the
RTD project). Existing versions keep building with the old Sphinx config until the
migration PR merges. Nothing here changes RTD project settings or DNS.

## 2026-09-11: Notebook link rewrite covers relative links only

MyST heading anchors are lowercase slugs (`#custom-environments`) whereas nbsphinx
produced `#Custom-environments`, and `.rst`/`.html` targets disappear. The ~45
relative links inside notebook markdown cells are rewritten by script with a printed
report of every change. The ~90 absolute `https://docs.maap-project.org/...` URLs
are left untouched: they keep working through generated redirect stubs for the old
`.html` paths (which also translate old-style anchors). Rewriting them to relative
links is a possible follow-up.

## 2026-09-11: Task runner is a plain `Makefile`, not `just`

The reference repo uses `just`. The user asked to avoid introducing new tools for
this repo. The old workflow was already `cd docs && make html`, so a top-level
`Makefile` keeps the same, well-known tool. `just` would have added only nicer
argument handling, which is not needed here.

## 2026-09-11: No notebook execution in CI or at build time

Executed notebooks are produced on the MAAP JupyterHub and committed. This matches
the current Sphinx setup (`nbsphinx_execute = 'never'`) and avoids needing MAAP
credentials, R kernels and DPS access in CI. A convenient end-user workflow for
"execute on the hub, then commit" is a later design task.

## 2026-09-11: Migration is script-generated and re-runnable

All conversion is done by scripts under `migration/` that start from the pristine
Sphinx tree, so the migration can be regenerated after in-flight PRs merge and the
diff is auditable. Hand edits to generated files are not allowed until cutover;
exceptions go in `migration/overrides.yml`.

## 2026-09-11: Claude never commits

All commits are made by the user after review.

## 2026-09-11: Page listed in three toctrees is listed once in the sidebar

`technical_tutorials/working_with_r/find_data_in_r` was in the Search, Access and
Working with R toctrees. In MyST a file listed twice in `project.toc` is built twice
(`…/find-data-in-r-1`), and a `url:` entry pointing at the page is written without
the site `BASE_URL` prefix (tested: `href="/technical-tutorials/…"` while file
entries get `/en/latest/…`), which would break under ReadTheDocs' version prefix.
Decision: the `file:` entry stays under Working with R (its folder), and the Search
and Access pages get an explicit markdown link right after their inline `{toc}`
list, generated by `build_toc.py`/`convert_rst.py`. The inline lists therefore match
the old pages; only the sidebar shows the entry once. Recorded as C6 in
`04-compromises.md`.

## 2026-09-11: `_static/custom.css` is replaced, not dropped

The old file only styled RTD-theme selectors. The new file (generated by
`write_config.py`, referenced via `site.options.style`) holds the one rule the spike
showed is needed: isolated notebook-output iframes (R htmlwidgets) at 100% width.

## 2026-09-11: `settings.output_matplotlib_strings: show`

mystmd's default (`remove-warn`) hides text/plain outputs that look like matplotlib
object reprs. nbsphinx showed every stored output, so the setting is `show`. The
verify script's output audit confirms every source output appears in the built pages.

## 2026-09-11: Redirect stubs are generated at build time, not committed

`migration/redirect_map.json` (committed, generated by `migrate.py`) lists every old
Sphinx URL and its new path. `migration/gen_redirects.py` writes one stub per old URL
into `_build/html` after `myst build` (locally via `make build`, on RTD via
`.readthedocs.yml`). Stubs use relative targets so they work under any URL prefix,
and translate old `#Title-Case` anchors to mystmd ids in the browser.

## 2026-09-11: Warnings left in the build log on purpose

- "Linking … to an implicit heading reference" (x3): mystmd's best-practice note

  notebooks' markdown beyond the migration's scope; left as is.
- "missing heading depth 3" (x2): two notebooks jump from `#` to `###`. Cosmetic;
  changing heading levels would alter content.
- "No target for internal reference "#"" (x3): placeholder `[text](#)` links that
  exist in the source today.
- "Cross reference target was not found: accessing-maap-workspaces-over-ssh": a
  pre-existing broken anchor (see `04-compromises.md`).
- "Image is too large … to convert to webp": informational.

## 2026-09-11: `make migrate` guard

`make migrate` restores `docs/source` from `develop` and runs `git clean -fd` on it,
which deletes untracked files there. During the session a `.gitignore` mistake (the
`_build/` line had been appended to the previous line) meant `_build` was not
ignored and got deleted by that step. `.gitignore` is fixed and `make migrate` now
refuses to run while `docs/source` has uncommitted changes (override with
`FORCE=1`). After the migration is merged, `make migrate` is no longer needed.

## 2026-10-15: syncing `develop` into the migration branch

The migration is frozen, so `develop` changes are merged with `git merge` and
ported by hand rather than by re-running the generator. First sync: `develop` at
`257139c` (merge-base `0dcbe21`). How each change was handled:

- **`.rst` pages** (`release_notes.rst`, `technical_tutorials.rst`) are deleted on
  this branch, so they come up as modify/delete conflicts. Port the diff into the
  `.md` page in its existing style, and toctree changes into `myst.yml`. This
  time: the 6.0.0 and 5.2.0 release notes, and `dps_stac_metadata.ipynb` moved
  from a hidden toc entry to visible after `dps_tutorial_demo.ipynb`. Absolute
  `docs.maap-project.org/...html` links in the release notes are left as they are
  (served by the redirect stubs, as for all absolute links).
- **`requirements.txt`** stays deleted. Develop added `requests` and `shapely`,
  but it was the Sphinx build's environment and notebooks are not executed at
  build time. The MyST build environment is `pyproject.toml` + `uv.lock`.
- **Raw reStructuredText cells.** PR #603 turned the HTML `alert-info` boxes in
  7 notebooks into raw cells with `raw_mimetype: text/restructuredtext` holding
  `.. note::`. nbsphinx rendered those as Sphinx notes; **MyST does not render
  raw RST cells at all**, so merged as-is the notes would silently vanish. Each
  is converted to a markdown cell holding a MyST `:::{note}` block: RST links
  become markdown links, relative `.html` links become `.ipynb` (same rule as
  the original link rewrite), cell id kept, `raw_mimetype`/`vscode` metadata
  dropped. Notebooks: `search/collections`, `search/granules`,
  `search/searching_edsc_gui`, `working_with_r/access_cmr_r`,
  `working_with_r/cmr_search_in_r`, `working_with_r/maap_stac_r`,
  `dps_tutorial/dps_stac_metadata`. For the conflicting notebooks develop's
  version was taken whole, so the only difference from `develop` is the converted
  cell. **Repeat this check on every future sync:**
  `grep -rl text/restructuredtext docs/source --include='*.ipynb'` must find nothing.
- **RST admonitions inside markdown cells** (added after the deployed-site
  check): nbsphinx rendered `.. note::` / `.. warning::` / `.. important::`
  lines in markdown cells as admonitions too, so they are converted the same
  way (see `04-compromises.md` C9). On every sync, this must print nothing
  (it covers both raw and markdown cells, and cells whose `source` is a single
  string, which a plain grep misses):

  ```
  python3 -c 'import json,glob,re; [print(p,i) for p in glob.glob("docs/source/**/*.ipynb",recursive=True) if "_build" not in p for i,c in enumerate(json.load(open(p))["cells"]) if c["cell_type"]!="code" and re.search(r"(?m)^\s*\.\. [a-z-]+::","".join(c["source"]))]'
  ```
- Clean merges (`work_with_git.ipynb`, `visualizing_titiler-pgstac.ipynb`, the
  three new `dps_tutorial/_static/*.png`) needed no changes.

## 2026-10-15: Trim `migration/` to the decision record before merging

The frozen migration scripts (`migrate.py` and its steps, `verify.py`, `checks/`,
`overrides.yml`) and the `migration` uv dependency group (pyyaml) are removed from

agent-docs too (the compromises list should stay next to the content).

Also added to `CONTRIBUTING.md`: "Adding a notebook or page". Checked with a real
build (a scratch notebook outside the toc, 2026-10-15): **a notebook that is not in
`project.toc` is not built, and mystmd prints no warning**, so the how-to says so.
It also covers MyST admonitions and the leftover-RST one-liner above, so that
contributors don't add `.. note::` again.
